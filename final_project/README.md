## What Is a Data Dictionary?

A **data dictionary** explains what the columns in a dataset mean.

If a dataset is a table, the data dictionary is the guide to reading the table.

It helps answer:

- What does each column mean?
- What kind of value belongs in each column?
- Are there missing values?
- Are there codes or categories that need explanation?
- Which columns might create security, privacy, or ethics concerns?

### Basic Terms

| Term | Meaning |
|---|---|
| Dataset | A collection of data. In this class, most datasets are tables. |
| Table | Data organized into rows and columns. |
| Row | One record. A row might represent one alert, complaint, inspection, vulnerability, or breach. |
| Column | One field or attribute about every row. |
| Value | The actual entry inside one cell. |

Example:

If each row is one security alert, columns might include:

- `alert_id`
- `severity`
- `confidence`
- `asset_id`
- `created_at`

If the column is `severity`, a value might be `high`, `medium`, or `low`.

### Why Data Dictionaries Matter

Without a data dictionary, a column name can be confusing.

| Column name | Possible confusion |
|---|---|
| `cmplnt_fr_dt` | What does this abbreviation mean? |
| `lat` | Is this latitude? Is it always present? |
| `boro` | Is this borough name, borough code, or something else? |
| `status` | What are the allowed status values? |

Security work depends on correct interpretation.
If you misunderstand a column, you can make the wrong decision.

Privacy and ethics also depend on understanding what the data represents.
Before analyzing a dataset, ask:

- Does the dataset describe people?
- Does it include location?
- Does it include time?
- Could different columns be combined to identify someone?
- Could the data be used to judge people or neighborhoods unfairly?
- Could missing data distort the conclusion?
