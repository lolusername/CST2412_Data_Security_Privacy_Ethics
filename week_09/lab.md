# Week 9 Lab: Easy GitHub Education + MongoDB Atlas Activity

**Course:** CST 2412 Data Security, Privacy, and Ethics  
**Work mode:** Individual  
**Time:** 55-70 minutes  
**What you submit:** 1 document with Sections A-E in order  
**Rule:** Use only the official URLs and your own account if you log in. No hacking, no scanning, and no credential sharing.

## Purpose
This is a guided, easy full-class activity.
You will use the official GitHub Education and MongoDB Atlas URLs to:
- identify the MongoDB-related student benefit
- learn basic Atlas vocabulary
- make a simple setup plan
- spot a few obvious cloud-security mistakes

## Official URLs
Use these official URLs:
- GitHub Education Pack: `https://education.github.com/pack`
- MongoDB Atlas free-cluster docs: `https://www.mongodb.com/docs/atlas/tutorial/deploy-free-tier-cluster/`

## Two valid paths
Choose **ONE**:

### Path A: Live review
Use this if you can log into your own GitHub/MongoDB account and inspect the pages directly.

### Path B: Documentation only
Use this if you cannot log in or just want to work from the public pages.

Both paths can earn full credit.

## What to submit
Turn in one document with:
1. Section A: URL check
2. Section B: Quick perk check
3. Section C: Atlas vocabulary
4. Section D: Safe setup checklist

## Section E: Short Safety Reflection

### Scenario
A student set up Atlas but:
- saved the password in a shared class document
- allowed access from `0.0.0.0/0`
- took a screenshot showing the connection string

### Task
Answer these:
1. Which mistake should be fixed **first**?
2. Why should that one come first?
3. Name **one** security principle that fits your answer:
   - confidentiality
   - least privilege
   - secure defaults

### Length
100-140 words

### Sentence starters
- `The first mistake that should be fixed is ______.`
- `This should come first because ______.`
- `The main security principle here is ______ because ______.`

## Grading lens
Full credit work will:
- use the correct official URLs
- explain Atlas vocabulary correctly
- show the setup steps in the right order
- identify one realistic security mistake clearly
- stay clear and simple

## Common mistakes to avoid
- mixing up a GitHub account with a database user
- treating `0.0.0.0/0` as harmless
- writing too much instead of answering clearly
- focusing only on the free credits and ignoring safe setup
